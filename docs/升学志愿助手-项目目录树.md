## 一、目录职责速查

| 目录 | 职责 | 一句话约束 |
|------|------|-----------|
| `backend/app/api/` | HTTP 入口 | **只做**校验/限流/取会话/调 service，禁写业务 |
| `backend/app/services/` | 业务逻辑 | 事务边界 + **口径唯一实现**（换算/推荐/时效/统计） |
| `backend/app/rag/` | 政策检索与问答 | 只基于检索到的 Context 生成；无依据兜底 |
| `backend/app/agent/` | 意图路由与编排 | Guardrails + Prompt 模板 + 输出后置校验 + SSE |
| `backend/app/core/` | 基础设施 | 配置/日志脱敏/限流/脱敏/LLM 客户端 |
| `backend/scripts/` | 数据管线 | fetch → clean → validate → import，**幂等** |
| `frontend/js/` | 前端逻辑 | **强制 ES Modules**；api/state/ui/router 分离 |
| `frontend/js/components/` | 复用组件 | 一个文件一个组件，禁把逻辑塞进 HTML |
| `data/` | 数据资产 | raw 留档 / cleaned 清洗 / eval 评测（不进产品库） |
| `docs/` | 文档 | PRD + 任务卡 + 口径 三件套为基线 |

## 二、关键约束（与任务卡呼应）

1. **单 HTML 原则的反面**：`index.html` 只是壳，所有逻辑在 `js/*.js`，用 `<script type="module">` 引入；
2. **前端零业务计算**：位次换算、冲稳保分档、容量校验一律后端做，前端只渲染；
3. **`.env` 全面接管**：数据库账密、`LLM_API_KEY`、`LLM_MODEL=deepseek-v4-flash`、年份配置、限流阈值全在其中，代码零硬编码；
4. **`data/raw` 与 `.env` 不入库**（`.gitignore`），避免敏感/大文件进 Git；
5. **敏感列**：档案表的分数/位次以 `score_hash`/`score_bucket` 落库，明文仅内存态使用；
6. **迁移即真相**：表结构以 `migrations/versions/` 为准，容器启动自动 `alembic upgrade head`。

## 三、本地开发启动（速记）

```bash
# 1. 基础设施（MySQL + Redis）
docker compose up -d mysql redis

# 2. 后端
cd backend && cp ../.env.example ../.env
uv run alembic upgrade head
uv run python scripts/import_data.py          # 导入清洗数据
uv run uvicorn app.main:app --reload          # http://127.0.0.1:8000/health

# 3. 前端（原生，无需构建）
cd ../frontend && python -m http.server 5173  # http://127.0.0.1:5173

# 4. 一键全量（含 API）
docker compose up -d --wait
```

### 4.2 ⚠️ 端口冲突（必须处理，否则起不来）

本机存在**两处端口冲突**，是本项目最容易卡住的地方：

| 端口 | 占用方 | 冲突后果 | 解决方案（本项目采用） |
|------|--------|----------|------------------------|
| **6379** | 遗留 v1 容器 `gaokao_redis`（已 Exited） | 新 Redis 起不来 | 起容器前先删除遗留容器（见下方命令） |
| **3306** | **本机 MySQL80 服务** | 容器 MySQL 起不来 | **直接复用本机 MySQL**，不用容器 MySQL（推荐）；或把容器映射改为 `3307` |
| 5432 | 遗留 v1 容器 `gaokao_postgres`（已 Exited） | 与 MySQL 无关，可清理 | 直接删除 |
| 5173 | 某进程（PID 21004）在监听 | 前端静态服务器起不来 | 换端口 `8080`，或先结束该进程 |

### 4.3 推荐的「本机开发」组合（最省事）

```
MySQL  → 复用本机 MySQL80 服务（3306），不用容器
Redis  → Docker 容器 redis:7 映射 6380（避开 6379 潜在冲突）
前端   → python -m http.server 8080（避开 5173 占用）
后端   → uvicorn 8000
```

**`.env` 对应配置**：

```env
DATABASE_URL=mysql+pymysql://root:你的密码@127.0.0.1:3306/gaokao?charset=utf8mb4
REDIS_URL=redis://127.0.0.1:6380/0
```

**动手前先清理 v1 遗留容器（一次性）**：

```bash
# 查看遗留容器
docker ps -a --filter "name=gaokao"

# 删除 v1 遗留（postgres 已不用；redis 会被新方案替代）
docker rm -f gaokao_postgres gaokao_redis

# 确认端口已释放（应无输出）
netstat -ano | grep -E ":6379|:5432"
```

### 4.4 用 Docker 起 Redis（唯一命令）

```bash
# 启动 Docker Desktop（若未启动）
"D:/Docker/software/docker_desktop/Docker Desktop.exe"

# 等待守护进程就绪
docker info

# 起 Redis（映射 6380 避开冲突，容器名 gaokao_redis）
docker run -d --name gaokao_redis \
  -p 6380:6379 \
  --restart unless-stopped \
  redis:7

# 验证（三步全过才算成功）
docker ps --filter "name=gaokao_redis"                # 状态 Up
docker exec gaokao_redis redis-cli PING               # 期望输出 PONG
docker exec gaokao_redis redis-cli SET k v && docker exec gaokao_redis redis-cli GET k
                                                      # 期望 OK / v
```

> 本项目最终会把 Redis 写进 `docker-compose.yml`（T01/T29），届时用 `docker compose up -d redis` 代替上面的 `docker run`，端口同样走 `6380`。

### 4.5 复用本机 MySQL 的准备（一次）

```bash
# 1. 用本机 MySQL 建库（Workbench 或命令行均可）
#    字符集必须 utf8mb4，否则中文校名/政策文本会乱码
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS gaokao DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"

# 2. 验证字符集
mysql -u root -p -e "SHOW CREATE DATABASE gaokao;"   # 应看到 utf8mb4

# 3. 验证时区（UTC 存储约定）
mysql -u root -p -e "SELECT @@global.time_zone, @@session.time_zone, NOW();"
```

> 若希望 MySQL 也走容器（与 T29 生产环境完全一致），把 `docker-compose.yml` 里 mysql 的映射端口改成 **3307**，避免与本机 `MySQL80` 抢占 3306。
