## 一、分层与职责（后端）

| 层 | 目录 | 只做什么 | 绝对不做 |
|---|---|---|---|
| 路由层 | `app/api/` | 参数校验、限流、取会话、调 service | 写业务逻辑、直接查库、拼 SQL |
| 业务层 | `app/services/` | 事务边界 + **口径唯一实现**（换算 / 推荐 / 时效 / 统计） | 处理 HTTP、返回 Response 对象 |
| 检索层 | `app/rag/` | 切片、索引、召回、重排、生成（**只基于检索 Context**） | 无依据时编造、绕过兜底 |
| 编排层 | `app/agent/` | 意图路由、Guardrails、Prompt、输出后置校验、SSE | 直接写库、绕过 RAG 约束 |
| 基础设施 | `app/core/` | 配置、日志脱敏、异常、Redis、**LLMClient** | 任何业务语义 |
| 数据层 | `app/db/` | 引擎 / Session / ORM 模型 | 业务判断 |
| 数据管线 | `scripts/` | fetch → clean → validate → import（**幂等**） | 被在线接口调用 |

**调用方向单向**：`api → services → (db / rag / core)`，禁止反向依赖或跨层直连。

---

## 二、命名与风格

- **PEP8 + ruff**，行长 **120**（`ruff check .` 必须 `All checks passed!`）；
- 文件 / 模块：`snake_case.py`；类：`PascalCase`；函数 / 变量：`snake_case`；常量：`UPPER_SNAKE`；
- 注释与文档字符串用**中文**，说明「为什么」而非「是什么」；
- 类型注解**必填**（函数签名全覆盖）；
- 前端：`camelCase` 变量 / 函数，`PascalCase` 组件文件，**一律 ES Module**（`import` / `export`）。

---

## 三、配置与密钥

- 所有可变参数走 **`.env`**（模板见 `.env.example`），代码经 `app.core.config.settings` 读取；
- **禁止**在代码中出现任何 API Key / 数据库账密 / Token 字面量；
- `.env` **绝不入库**（已 `.gitignore`）；
- 新增配置项必须**同时**更新 `.env.example` 与 `config.py`。

---

## 四、LLM 使用规范（重要）

- 业务代码**禁止硬编码模型名**，一律通过 `get_llm_client()` 注入；
- 模型链由 `LLM_MODEL`（主）+ `LLM_MODELS`（降级链）配置；主模型超时 / 5xx / 停服 / 欠费自动 failover；
- 全链失败抛 `LLMError`，上层**必须**切换到「专家规则模式」本地兜底，不得直接报错给用户；
- `MOCK_MODE=true` 时确定性 mock，**无需 key 可跑通全链路**（CI / 演示用）；
- 响应须携带**实际使用**的 `model` 字段，便于追溯。

---

## 五、数据与合规红线（不可违背）

1. **推荐 / 回答必须有库内依据**；无数据必须显式标注；宁可少推不可错推；
2. 所有 AI 输出**必带免责声明**「本建议仅供参考，不作为最终填报承诺」；**禁止输出录取概率数字**；
3. AI **只答**升学 / 专业 / 大学规划；无关问题拒答并引导；抗提示注入；
4. **RAG 必须且只能基于检索到的 Context**；无依据走兜底不生成；回答带引用（标题 + URL）；
5. 敏感字段（分数 / 位次）脱敏落库（`score_hash` + `score_bucket`），**日志禁明文考分 / 身份**；
6. 年份维度贯穿：推荐只用 `≤ CURRENT_YEAR` 数据；系数 / 口径**只在一处实现**；
7. 前端强制 **ES Modules**（api / state / ui / router 分离），禁框架、禁单 HTML 塞逻辑。

## 六、Git 与协作

- **一张任务卡 = 一次会话 = 一个 commit**，提交信息格式：`Txx: 描述`（如 `T01: 工程初始化与开发约定`）；
- 每个 P 段结束人工过 **Gate** 才进下一段；
- 提交前必须：`uv run ruff check .` 通过、`uv run pytest` 通过；
- 不提交 `.env`、`data/raw/`、`node_modules/`、构建产物。

## 七、反面清单（❌ 出现即返工）

| ❌ 反面做法 | 为什么禁止 |
|---|---|
| 在 service 里写死 `"deepseek-v4-flash"` | 模型停服即全线不可用；破坏可切换性 |
| 路由层直接 `db.query(...)` 拼业务 | 破坏分层，事务边界失控 |
| RAG 无检索结果时让模型「自由发挥」 | 幻觉源头，违反防幻觉红线 |
| 输出录取概率（如「录取概率 78%」） | 违反产品红线，误导用户 |
| `logger.info(f"分数={score}")` 打明文 | 违反 PIPL 脱敏要求 |
| 把逻辑写进 `index.html` 的 `<script>` | 违反单 HTML 原则的反面 |
| 引入 React / Vue / 向量库 | 与既定技术栈冲突（重型依赖） |
| 前后端口径各算一套（前端也实现冲稳保） | 口径必须唯一实现（后端） |
| 硬编码 API Key / 数据库密码 | 安全红线 |
| 新增目录不同步更新目录树文档 | 架构漂移 |
